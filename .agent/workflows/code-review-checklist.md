# 代码审查清单

在提交 Pull Request 或进行代码审查时使用此清单,确保代码质量和一致性。

## 代码质量

- [ ] **代码风格**: 符合 PEP 8 (Python) / Prettier (TypeScript) 规范
- [ ] **命名规范**: 变量、函数、类名清晰且符合约定
- [ ] **类型注解**: Python 函数有完整类型提示,TypeScript 无 `any` 类型
- [ ] **文档字符串**: 公共函数/类有 docstring/JSDoc
- [ ] **注释质量**: 注释解释 Why 而非 What

## 架构和设计

- [ ] **分层架构**: 遵循 API → Service → Repository 分层
- [ ] **单一职责**: 每个函数/类只做一件事
- [ ] **依赖注入**: 使用 FastAPI Depends 或 React Props
- [ ] **避免重复**: 复用逻辑已提取为函数/组件
- [ ] **错误处理**: 有适当的异常处理和日志记录

## 测试

- [ ] **单元测试**: 新功能有单元测试(覆盖率 ≥ 80%)
- [ ] **集成测试**: 关键路径有集成测试
- [ ] **测试命名**: 测试名称清晰描述测试场景
- [ ] **测试隔离**: 测试之间相互独立
- [ ] **所有测试通过**: `pytest` / `npm test` 全部通过

## API 设计(如适用)

- [ ] **RESTful**: 使用标准 HTTP 方法和资源命名
- [ ] **统一响应**: 使用 `{success, data, error, meta}` 格式
- [ ] **Pydantic 验证**: 请求/响应使用 Pydantic 模型
- [ ] **错误处理**: 返回适当的 HTTP 状态码和错误信息
- [ ] **API 文档**: 端点有 summary 和 description

## 安全性

- [ ] **输入验证**: 所有用户输入经过验证
- [ ] **SQL 注入**: 使用 ORM,避免原始 SQL
- [ ] **XSS 防护**: 前端输出已转义
- [ ] **敏感信息**: 密钥、密码不硬编码,使用环境变量
- [ ] **认证授权**: 需要保护的端点有认证检查

## 性能

- [ ] **异步 I/O**: 后端 I/O 操作使用 `async/await`
- [ ] **数据库查询**: 避免 N+1 查询,使用适当的索引
- [ ] **前端性能**: 避免不必要的重渲染,使用 memo/useMemo
- [ ] **资源清理**: WebSocket/文件句柄正确关闭

## 文档

- [ ] **README 更新**: 如有新功能,更新 README
- [ ] **API 文档**: OpenAPI 文档已更新
- [ ] **迁移说明**: 如有数据库变更,提供迁移脚本
- [ ] **配置说明**: 新增环境变量已文档化

## 提交前最后检查

- [ ] **无调试代码**: 移除 `console.log` / `print` 调试语句
- [ ] **无注释代码**: 删除无用的注释代码
- [ ] **格式化**: 运行 Black / Prettier 格式化代码
- [ ] **Lint 检查**: 无 ESLint / Pylint 警告
- [ ] **提交信息**: Commit message 清晰描述变更

## 审查者注意事项

- 关注业务逻辑正确性,而非代码风格细节
- 提出建设性意见,说明原因
- 如有重大架构变更,建议先讨论设计
